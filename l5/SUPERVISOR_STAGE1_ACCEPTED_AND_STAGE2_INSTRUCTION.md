## 2. 为什么后续汇报格式必须改

后续每一次 worker 完成任务，不能只回复“完成”“Commit SHA”“Current HEAD”。

这会导致监工和用户无法知道：

- 最终 PPT 文件到底是哪一个；
- 文件位于 GitHub 什么路径；
- 本轮实际修改了哪些页；
- 渲染图在哪里；
- 对照图在哪里；
- contact sheet 在哪里；
- build report 在哪里；
- 哪一个提交是真正生成 PPT 的 generation commit；
- 哪一个提交只是 packaging / trigger commit。

因此从第二阶段开始，**最终回复格式为硬性要求**，不得省略。

## 4. 第二阶段最高优先级视觉红线

### A. 最终视觉稿优先

每页必须以 LibreOffice / PowerPoint 实际渲染后的页面为验收对象。

禁止用：

- XML 没报错；
- shape 坐标在版心内；
- workflow passed；
- build report 自称 passed；

代替肉眼视觉验收。

### B. 禁止 Placeholder

不得出现任何：

- 原设备照片
- 原图示意
- 待替换
- 此处放图
- 右侧显微图
- Placeholder

等占位内容。

### C. 禁止施工说明进入学生 PPT

不得出现：

- 本页已重建
- 已删除残留
- 已完成中文化
- 为避免压字
- 保留原始信息
- 本页采用……方案

等制作说明。

### D. 禁止“英文原页缩小 + 中文摘要”

页面主体不能继续依赖缩小的原英文整页承担教学内容。

若必须保留原科学图：

- 必须干净裁取；
- 去掉原页标题条、页码、重复网址和无关正文；
- 中文说明不得以多个红框贴纸堆在原图周围；
- 中文标签必须与对象/箭头建立清晰对应关系。

### E. 科学内容不可修改

不得擅自简化、改写：

- 公式；
- 物理关系；
- 化学反应式；
- 状态数；
- 图中箭头；
- 能级关系；
- 方法名称；
- 原教材图的关键教学逻辑。

重绘不等于自由重解释。
